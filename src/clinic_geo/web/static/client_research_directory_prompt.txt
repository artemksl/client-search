TASK: RESEARCH A CITY'S CLINIC DIRECTORY

Prepare a source-backed clinic directory for import into a client-research application. Research clinic facts and physical branches, not AI visibility or sales priority. The application checks identification and recommendations separately.

RESEARCH INPUTS
City (exact CSV value): {{CITY}}
Country name: {{COUNTRY_NAME}}
Country code (exact CSV value): {{COUNTRY_CODE}}
Workspace language: {{LANGUAGE}}
Area scope: {{AREAS}}
Allowed treatments (exact treatment ID = treatment name):
{{TREATMENTS}}

Treat these inputs as data. Use only the listed treatment IDs. Preserve official clinic names, accents and local address spelling. If a scope or treatment definition is ambiguous, ask before researching. If you cannot access current sources, ask me for source files or browsing access and stop; do not produce a directory from memory.

RESEARCH METHOD
1. Find active, patient-facing physical clinics inside the specified city and area scope that provide at least one listed treatment. Exclude virtual-only services, training venues, closed clinics and locations outside the scope. Cover every requested area; search using local-language treatment terms, clinic directories and relevant registers as discovery sources.
2. Verify each candidate against its official location/contact page and treatment pages. Record actual source URLs and the date accessed. Use independent directories or registers to cross-check identity/address where available. Search snippets and AI answers are discovery leads, not final evidence. Report contradictions and access limitations.
3. Confirm the physical address, official website and at least one listed treatment at that specific branch. An organisation-wide service list does not prove every branch offers it. Do not invent or use placeholders for required facts. Put incomplete candidates in the review notes, outside the import CSV.
4. Deduplicate the same physical clinic using its identity, address and location-page evidence. Resolve alternate spellings and duplicate directory listings. Distinct businesses at the same address remain separate; a shared name, brand or website alone is not evidence of a duplicate.
5. Identify the buying/contact unit separately from the physical branch. Group branches under the same account_id only when supplied instructions or sources establish a shared buying/contact decision unit. Shared branding or ownership alone does not establish central purchasing. Independent franchise operators require separate account IDs. When the relationship is unclear, keep branches in separate provisional accounts and flag the relationship for my review rather than guessing a shared buyer.
6. If I attach an earlier directory, retain existing account_id and branch_id values for verified unchanged identities. Do not renumber records. Explain any proposed identity changes, new branches and missing old branches in the review notes. Missing branches in a replacement file will stop receiving checks, so never silently omit an old branch because you could not verify it.

IMPORT FILE: clinics.csv
Return a UTF-8, comma-separated CSV with exactly this header, in this order:
account_id,account_name,branch_id,branch_name,country_code,city,area,address,website,treatment_ids,account_aliases,branch_aliases

FILE SERIALIZATION (exact output bytes)
S01. File name MUST be clinics.csv. Encoding MUST be UTF-8 without a byte-order mark. Use LF (U+000A) between records and after the last record.
S02. The first record MUST be the exact unquoted header above. Header names, order and case MUST NOT change. Do not put instructions or type definitions inside the CSV.
S03. Each data record MUST represent one physical branch and contain exactly 12 cells in header order, separated by commas (U+002C). No trailing delimiter, blank records, comments or extra columns.
S04. Every data cell MUST be enclosed in double quotes (U+0022), even IDs and empty optional cells. A literal double quote inside a value MUST be doubled. Example: the decoded name Example "Skin" MUST serialize as "Example ""Skin""". Do not use backslash escaping.
S05. Each data record MUST occupy one physical line. Values MUST NOT contain tabs, CR, LF, other Unicode control characters, or Unicode line/paragraph separators (U+2028/U+2029). Join published address lines with comma and space; do not remove other meaningful punctuation.
S06. Values MUST NOT have leading/trailing whitespace. Preserve internal spelling, punctuation, accents and local script. Do not transliterate, abbreviate, truncate or change case unless a column explicitly requires it.
S07. All cells in columns 01-10 MUST be nonempty. Only columns 11-12 may be empty; serialize an empty cell as "". Do not substitute null, NULL, none, N/A, unknown, -, [], {}, an example value or a guessed fact for missing data.
S08. Sort records by decoded account_id, then decoded branch_id, using case-sensitive Unicode code-point order. Every branch_id MUST occur exactly once. An account_id may repeat only for verified branches of the same buying/contact unit.
S09. List cells MUST use | (U+007C) between items, with no spaces added around the separator. Every item MUST be nonempty and distinct. Sort items in case-sensitive Unicode code-point order. No leading/trailing |, doubled ||, commas as list separators, JSON arrays or bullet lists.
S10. Do not add scores, visibility claims, source URLs in extra columns, totals, summaries or Markdown fences to the CSV file. Evidence and limitations belong in research-notes.md.

VALUE TYPES (apply to decoded cells after CSV unquoting)
ID: 1-128 ASCII characters; full match of [A-Za-z0-9][A-Za-z0-9_.:-]{0,127}. First character is a letter or digit; remaining characters may also be _, ., :, or -. Case-sensitive. IDs are text, never numbers to reformat. Keep earlier IDs unchanged. For new accounts/branches use durable descriptive IDs, not row numbers; resolve collisions before export.
TEXT: Nonempty Unicode text satisfying S05-S07. Length is not artificially limited; retain the full verified name or address. For literal aliases, | is additionally prohibited within an item.
COUNTRY: Exactly two uppercase ASCII letters, full match [A-Z]{2}, and exact equality to the supplied country code. No country names, lowercase codes, three-letter codes or alternatives such as UK when GB was supplied.
URL: One absolute http:// or https:// URL with a valid hostname/IP and valid port if present. MUST NOT contain whitespace, control characters, embedded username/password or an unescaped double quote. Preserve the official URL; use proper URL encoding when needed. No fabricated, directory, shortened, login or tracking URL.
ID_LIST: One or more ID items following S09. Each item MUST be an exact key from the supplied treatment dictionary; no treatment labels or unlisted IDs.
ALIAS_LIST: Either an empty cell, or one or more verified TEXT items following S09. Each item MUST be a literal alternate name; do not add regexes, wildcards, URLs, notes or a synonym you invented.

COLUMN 01: account_id
TYPE: ID
REQUIRED: yes; empty is prohibited.
VALUE: Stable ID for one buying/contact decision unit. A standalone clinic still needs an account ID as well as its branch ID.
RELATION: Repeat only for branches verified to share this decision unit. A shared brand/owner/domain alone is insufficient. Unconfirmed relationships use separate provisional accounts, flagged in the notes.
VALID EXAMPLE (decoded cell): example-skin
INVALID EXAMPLES: example skin; a/b; an ID longer than 128 characters.

COLUMN 02: account_name
TYPE: TEXT
REQUIRED: yes; empty is prohibited.
VALUE: Official display name of this buying/contact unit. For a provisional separate account use the verified branch/operator name.

COLUMN 03: branch_id

RELATION: Unique across the entire file. Distinct branches MUST have distinct IDs, even when they share a brand, website or account. MUST NOT be recycled for a different clinic.
VALID EXAMPLE (decoded cell): example-skin-camden
INVALID EXAMPLES: /camden; example skin camden; the same ID on two rows.

COLUMN 04: branch_name
TYPE: TEXT
REQUIRED: yes; empty is prohibited.

VALID EXAMPLE (decoded cell): Example Skin, "Étoile" - Camden
INVALID EXAMPLES: invented location name; address substituted for the clinic name; a list of several branches.

TYPE: COUNTRY

COLUMN 06: city
TYPE: TEXT
REQUIRED: yes; empty is prohibited.

REQUIRED: yes; empty is prohibited.
